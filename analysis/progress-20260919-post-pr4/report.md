## 不能高估进度的具体证据

- `tools/check_migration_boundaries.py` 通过：197 个源/头文件没有手写 inline asm 或 naked 入口，原反编译参考完整。但机器指令辅助函数仍存在：58 个定义、57 个在扫描源文件出现，共 2,076 处词法引用（前次 2,135）。引用不等于动态调用或链接存活。
- 扫描 C++ 实现有 916 处 `field<...>` 访问；这不是 916 个错误，但说明整数地址/原布局适配仍很普遍。`act_document.cpp`、`act_layout.cpp` 直接保留多个数值偏移。
- `legacy_frame_copy.cpp` 仍依据栈帧候选评分猜测 memcpy 操作数；ABI 隔离和契约通过不等于每个旧调用点已恢复显式参数。
- `squirrel_vm_bootstrap.cpp` 仍有 g642/g643/g644/g645 和 function_地址接口，并明确记录原虚拟清理接收者未恢复，不宜称为完整 RAII 所有权重建。
- `retdec_runtime_compat.cpp` 仍有部分返回零的兼容入口；必须先证明其可达性，不能按数量推定游戏缺陷。

## 下一步建议

1. 先建立最新 EXE 的链接存活清单：原地址→当前语义函数/第三方源码/不存活→验证用例。重点处理 504 个未映射独立入口和指令/CRT 兼容引用；不要按词法无引用直接删虚表目标。
2. 收尾 ACT→对象创建→回调→释放这一条链，把现有 C++ 的偏移 view 提升为字段名/类型/所有权；逐个消除 `_memcpy2` 的隐式操作数。
3. 再按 Actor/场景、渲染资源、输入/音频/存档迁移，最后删除确认无用的旧 C 和压缩 ABI 边界。每批继续诊断/无日志及原 DAT 冒烟验证。

暂不把剩余比例换算为天数；缺少链接存活清单和稳定的每批迁移成本数据。大块 CRT/模板代码可整组替换，小型生命周期函数却可能更昂贵。
