# 函数恢复状态及剩余工作估计

日期：2026-09-18；复核代码：`59fe9e044941b5894f333b4419565d3655a4462f`。
本批只做源码统计及原版 IDA MCP 只读核对，没有修改运行逻辑、构建或运行游戏。

## 统计口径

重算既有 inventory 的词法分类，并将原反编译文件的全部 4,890 个唯一
`function_地址` 逐项查询原版 IDA 函数归属：

- 3,241 个是 IDA 独立函数起点。
- 1,615 个位于其他函数内部，包括旧异常清理片段。
- 34 个地址未获得 IDA 函数归属，需要进一步判定。

下面的“独立入口”是 **RetDec 地址清单与 IDA 函数起点的交集**，不是原版整个 EXE
的完整函数清单。先前 IDA survey 共识别 3,963 个函数，不能把其余 722 个直接叫作
缺失实现；本脚本没有逐项解释这部分差集。第三方源码、导入/命名运行库函数和新辅助
函数也不能直接混入这个分母。IDA 函数边界本身仍是分析结果，不是绝对真值。

可明确定位替代实现的独立入口至少 **195** 个（177+18）；另有 **464** 个改动过的
独立入口。这两项不是“已恢复总数”的上限或等价性证明。Squirrel 源码替代一整组旧
函数时，不需要保留每个旧名字；游戏端的语义命名替代也会被简单地址匹配漏掉。

## 明确存在的待核实风险

- `retdec_asm_stubs.h/.c` 有 **58** 个统一返回零的机器指令辅助定义；CMake 显式
  列出的项目源文件中检出 **2,135** 处名字后跟括号的词法引用，其中 `__asm_int3`
  占 **775** 处。这是源码引用，不是动态调用次数，也不是链接存活数量。
- `src/platform/retdec_runtime_compat.cpp` 仍有异常、CRT 等简化兼容实现。
  本次没有为这些不同性质的兼容函数赋予一个“未恢复总数”。
- 主 C 文件仍有 **194,035** 物理行、**8** 处内联汇编。内联汇编并不自动表示错误，
  但调用约定和接收者依赖应在迁移前核实。

因此，“已经发现多少未恢复游戏函数”的严格答案仍是 **未确定**，不能写成零，
也不能把上述 58、502、1,836 相加。它们不是同一口径，而且辅助占位的调用者可能
已经被链接器裁掉。

## 剩余工作预算

工作目标必须分开：

1. **保持原 DAT 可玩并接近原版**：主要运行链已经具备，用户反馈支持常用玩法的
   高一致性。但剩余工作集中在可达风险、错误路径和未覆盖场景，不宜给功能完成率。
2. **形成便于加内容、长期维护的 C++ 工程**：沿用当前工程评估，暂按完成约
   30–40%、剩余约 60–70% 规划，置信度低。这是系统整理与验证预算，绝非还缺
   60–70% 游戏功能，也不是从函数数或 C++ 行数推导出来。

建议按以下顺序安排工作包（范围是初始规划估计，不是实测速度或工期承诺）：

| 工作包 | 预计规模 | 验收结果 |
|---|---|---|
| 链接存活清单、502 个未映射独立入口及 58 个辅助占位的调用者归类 | 2–4 个集中批次 | 原地址→现实现/库替代/不存活→验证依据；先缩小真实问题范围 |
| 对确认可达的接收者、异常/生命周期、加载和保存边界恢复与回归 | 3–8 个批次，需上一步校准 | 每批一个明确调用链，诊断/无日志构建与契约验证 |
| 按加载/对象、Actor/场景、渲染资源、输入/音频/存档整理可维护模块 | 约 10–20 个批次，波动大 | 类型、所有权、语义命名和原版行为证据完整 |

“批次”指一个可独立提交、验证、回查的有限功能改动，不等于一天或一次对话。
三行是不同阶段，范围可能重叠，不应机械相加为精确工期。没有可达清单和稳定的每批
耗时记录前，换算成人日不可靠。最值得优先投入的是第一行，它决定后续究竟需要修复
多少功能、哪些旧函数可以直接移除、哪些适合整库替代。
