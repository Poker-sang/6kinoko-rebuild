## 删除依据

`tools/audit_legacy_reachability.py` 默认只审计。根包括主 C 的数据/虚表初始化、所有非地址命名 helper、其他 src/include/tests 源和头文件引用、十进制/十六进制地址字面量，以及基线 Release 链接 map 中的函数名。按全部条件分支建立引用闭包，地址后缀和 retdec_unbound 旧副本分别识别。

没有只凭“没有直接调用者”删除：对基线 map 可见的候选一律作为根保留，再做闭包。最终删除项没有基线 map 符号。记录每个定义的原行、区间和 SHA256；应用时核对源文件及定义哈希，拒绝重叠区间。工具现在还要求 map 旁的 source-commit.txt 对应当前 HEAD，且 src/include/CMakeLists.txt 没有偏离该提交的修改。

`removed-definitions.json` 保存清单与 map 哈希。原版 IDA MCP 的 survey、纹理构造/释放抽查、最大删除项原版 xref 抽查和 ACT 构造/析构伪代码均在本目录。原版仍有 xref 不意味着新程序需要旧实现，因此不以原版 xref 缺失为删除条件。辅助查看了提供的 Squirrel 2.2.2 源码及既有 sqvm.obj 反汇编中 Execute/CallNative；没有声称做了新一轮全量 VM 二进制等价比较。

删除后第一批保留的 1,346 个主 C 定义，其非空白源码全部与基线相同。前后 map 的名字集合有变化：933→906，30 个旧名字不再出现、3 个名字新出现；那 30 个定义全部仍在源码中且函数体未变。源码裁剪会影响优化/内联/ICF 展示，不能据 map 数量差直接判定功能减少，也不把 map 相似度当等价证明。

## 统计工具纠正

此前宽松正则会把 `if (function_xxx() == 0) {...}` 识别成嵌套函数定义；因此旧报告的“定义数”（例如 3,482）不是精确函数数。新工具限定真正的返回类型和定义行，基线实际匹配 3,326 个定义，本批清理后为 1,346 个，再迁出两个地址入口后主 C 为 1,344 个。旧报告保持历史原貌，不覆盖其产物。

三个 Python 回归用例覆盖条件调用不算定义、调用/初始化不算原型、注释/字符串/条件分支处理。旧报告基于唯一地址的类别也属于词法近似，不能把它当作等价性证明。

## 所有权与类型进展

1. 纹理：加载成功后的 COM 引用由局部 ComOwner 接管；注册成功才转交给 store。GetTexture 得到的临时引用也有明确作用域。最终释放仍先解绑八个设备阶段、再释放纹理、再清空借用 slot/名称；不增加全局析构清理顺序。
2. 扩展纹理契约：同纹理在两个阶段绑定、无关阶段引用保留、GetTexture 引用平衡、容量满时加载到的新对象只释放一次，并保留既有 5,000 次复用循环。
3. ACT：新增 `act_resource_records.hpp`，描述 192 字节 RuntimeRecord、344 字节 FindNode，关键字段有 offsetof/sizeof 断言；未知区域仍明确标为 unknown，不推测新游戏含义。
4. `act_runtime_lifecycle.cpp` 用具名字段及 RecordView 处理构造和释放。原版 44FDE0 的坏分配分支确实抛 bad_alloc；现在由真实 C++ 异常表达，去掉 RetDec 的假 SEH/连续 int3 和串入的异常清理片段。成功路径保留选择性写入，不把整个对象清零。
5. 场景清理复用 RuntimeRecord 的 ACT 字段，清楚区分 source holder、拥有的克隆和旧借用 fixture；保留解绑借用后释放 source、再析构 runtime 的顺序。
6. 既有资源清理的 stop→环境注销→FindClose 树→critical section→名字→向量→辅助存储→ACT 克隆→VM 外部引用顺序保持。没有顺便改写原加载流程、脚本或存档格式。
7. 新构造断言检查 owner、空脚本对象、树 sentinel、自环和 unknown 字节保留；原有场景反复释放及原 DAT 契约继续执行。
