# 主分支合并后函数与可维护性盘点

分析日期：2026-09-18。代码基线：`3cffc802f4c54ebb5ac1b9c5dfb5482e0be84547`，PR #2 合并后的 master。已切回 master 并 fast-forward 拉取。本批只生成分析文件，没有改运行代码，没有重新构建或宣称完成游戏验证。

## 结论与完成度口径

Squirrel 核心运行时已经实际使用提供的 C++ 源码，不再是仅将核心库编译进工程而继续默认执行旧 VM。SqPlus/Sqrat、原生参数与属性、原生调用、ACT 对象生命周期已有明确类型、所有权约束和回归测试的 C++ 实现。游戏本体仍依赖大型 RetDec C 文件和原始 Win32 内存布局。

若目标是“保留原版行为，同时让整个项目成为可读、可维护的 C++”，建议规划上暂按 **完成约 30–40%，剩余约 60–70%** 看待。这是对剩余系统重建与验证工作的低置信度工程估计，**不是下面任何计数的换算结果，也不是可验证的完成率或工期承诺**。目前没有全程序存活函数清单、完整地址替代映射或全关卡差分覆盖，不能给出可信的单一精确百分比。剩余工作大于简单删库函数和改扩展名；同时不能把每行保留的旧 CRT/codec 都按必须手工重写计入工期。

“修改过”的数量下降不是退步：很多修改过的 C 入口被进一步迁往独立 C++ 或删除。1,307 个缺少同名定义不等于缺少功能，也不等于 1,307 个全部完成重构。`metrics.json` 提供可机械确认的同地址 C++ 定义、显式 `_this` 和历史删除清单匹配；并未将所有其余条目逐项建立替代映射。仅同地址 C++ 定义已匹配 177 个，仍在主 C 文件的显式 `_this` 替代匹配 19 个；重命名为语义名称的替代不会被这个简单匹配全部发现。

96 个候选已另用 IDA 核对：**96/96 都不是 IDA 独立函数起点**，属于其他函数的内部片段。在 CMake 显式列出的项目 `.c/.cpp` 中，每个名字恰好出现两次（主 C 文件声明和定义）。例如 `4CCC00` 实际属于 `48BA20` 的 SQClosure 构造函数。应作为旧异常清理/内部片段残留继续做链接与引用清理，不能称为缺失 96 项游戏功能，也不应算作可维护实现。这个检查不排除未列入扫描的头文件、宏或原始数值地址引用。

## 建议下一步顺序

1. 为实际游戏 EXE 生成链接 map/PDB 存活清单，建立“原地址 → C++/库替代 → 调用者 → 测试”的映射。先清理被源码库替代后的僵尸实现、96 个内部片段、CRT/异常展开残留。不要只按源码无调用就删除可能的虚表目标。
2. 选一个完整垂直路径迁移：DAT/ACT 加载 → 原生对象创建 → 回调 → 释放。用语义命名、明确字段和 RAII 收拢接口，保持原版加载逻辑自然呈现行为。
3. 依次迁移 Actor/场景调度、渲染资源、输入/音频/存档，减少跨语言裸地址接口；最后收敛剩余 ECX/ESI/x87 与 `_memcpy2` 调用者帧依赖。
4. 每批保留诊断/无日志构建及契约回归；需要游戏验证时按既定范围进入第一关、跳跃、看到怪物后退出。自动测试通过和用户此前的主观成功反馈不能代替所有关卡/错误路径的等价证明。
