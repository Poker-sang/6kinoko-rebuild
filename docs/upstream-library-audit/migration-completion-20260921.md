## Boundary rules

No modern STL object is overlaid on generated byte records. Native owners are
allocated normally; game offsets hold opaque owners and/or borrowed views.
Payload lifetime remains separate where the original container stored borrowed
pointers. The map sprite records retain their copied byte counts and vtable
transitions. ACT publication preserves partial-load cleanup and cloning rollback.
String contents, embedded NUL handling, aliasing and truncation are retained;
historical SSO addresses and capacity growth constants are deliberately retired.

Residual malloc/free calls own game records, raw file/PCM/script payloads or
legacy allocator ABI results. They do not implement container growth, tree
balancing, hash buckets, reference counts or string SSO. Read-only VM snapshots
and old function-name forwards are compatibility/diagnostic boundaries.
